# OmniCoreAgent Cleanup Scratchpad

Local-only file. This path is excluded in `.git/info/exclude`, so it should not be committed or pushed.

## Current Goal

Keep improving OmniCoreAgent as a clean, production-grade agent harness before adding new features.

The work should stay focused on reliability, deterministic behavior, clean architecture, startup speed, testability, and making the codebase easy for another engineer or agent to navigate.

## Cleanup Order

1. Guardrails
2. Workspace architecture
3. Utils cleanup
4. System prompt cleanup
5. OmniServe
6. Background agents

## 1. Guardrails

Why this comes first:
- It is security-sensitive.
- It has had bugs before around scrubbing and false positives.
- It must be deterministic, efficient, and easy to test.
- Current file is still large and should not remain a mixed dump of patterns, detection, scrubbing, policy, and result formatting.

Target direction:
- Split `core/guardrails.py` into a focused package.
- Keep behavior stable unless a test proves current behavior is wrong.
- Add focused edge-case tests before/while moving logic.
- Avoid vague LLM-style judgment in this layer; guardrail behavior should be deterministic code.

Possible package shape:

```text
core/guardrails/
  __init__.py
  patterns.py
  detectors.py
  scrubbers.py
  policy.py
  result.py
```

Success criteria:
- Existing guardrail tests pass.
- More edge cases are covered.
- Scrubbing behavior is predictable.
- The public import surface remains simple.
- It is obvious where to fix detection versus scrubbing versus policy.

## 2. Workspace Architecture

Why this comes after guardrails:
- Workspace is central to artifacts, workspace files, scratchpads, task outputs, logs, and memory-like filesystem storage.
- It has improved already, but we still need to make it cleaner and more explicit.
- Local/S3/R2 should feel like one workspace abstraction, not scattered storage decisions.

Target direction:
- Review `workspace.py`, `workspace_config.py`, `workspace_storage.py`, and `tools/workspace_files/*` as one unit.
- Make workspace the clear entry point for file-backed agent state.
- Keep local and S3/R2 behavior equivalent from the caller’s point of view.
- Remove env-driven hidden behavior where explicit runtime config is better.

Success criteria:
- A caller can understand how workspace storage is selected.
- Artifacts and workspace files go through the same clean abstraction.
- Tests cover local and S3-compatible behavior.
- No duplicate storage logic is scattered across tools.

## 3. Utils Cleanup

Why:
- `core/utils.py` is still too large.
- It likely contains unrelated helpers that should live near the domain that uses them.
- Some helpers may no longer be needed after previous refactors.

Target direction:
- Audit every helper.
- Delete unused helpers.
- Move helpers close to the domain that owns them.
- Split shared helpers only when they are genuinely shared.
- Avoid creating a new dump-yard package.

Success criteria:
- `utils.py` becomes small or disappears.
- Import paths communicate purpose.
- Startup/import tests remain fast.
- No circular imports introduced.

## 4. System Prompt Cleanup

Why:
- `core/system_prompts.py` is still large.
- Prompt content is part of the harness and must be easy to reason about.
- We do not want prompt fragments scattered across many unrelated modules again.

Target direction:
- Keep one clear prompt ownership area.
- Split by prompt purpose if needed, not randomly.
- Make prompt context assembly explicit and testable.
- Keep the multi-tool-use guidance clear and not duplicated.

Success criteria:
- Prompt architecture is easy to navigate.
- Prompt tests cover the important generated sections.
- No stale DeepAgent or old ReAct prompt leftovers.
- No duplicate prompt rules fighting each other.

## 5. OmniServe

Why:
- OmniServe is the production serving surface.
- We should clean this before treating the whole system as production-grade.
- Serve should be understandable, testable, and not overclaim features.

Target direction:
- Review `serve/*` after core harness cleanup.
- Keep API, lifecycle, routing, middleware, metrics, and event streaming separated cleanly.
- Do not add new trace/evaluation/feedback features yet.
- Keep docs honest about what exists.

Success criteria:
- Serve structure is clear.
- Tests cover core API behavior and failure cases.
- Docs match implementation.

## 6. Background Agents

Why this comes last:
- It is a separate feature surface.
- It is not the main path right now.
- It should not distract from the core harness and serve cleanup.

Target direction:
- Return after guardrails, workspace, utils, prompts, and OmniServe are stable.
- Decide whether background agents stay as-is, become optional, or need deeper redesign.

Success criteria:
- Background agent code is isolated.
- Optional dependencies and startup cost stay controlled.
- Tests cover lifecycle and scheduler behavior.

## Stop Conditions For Cleanup

Stop broad cleanup when:
- Runtime, tools, MCP, workspace, memory, prompts, serve, and agents are easy to find.
- Large dump-yard files are gone or reduced to clear facades.
- Security-sensitive behavior has deterministic tests.
- Full test suite stays green after each PR.
- Docs describe actual shipped behavior.
- New features can be added without patching unrelated layers.

## Current Workspace PR Notes

Workspace design:
- `core/workspace` owns workspace config, storage, path normalization, file operations, artifact offloading, artifact tools, and offload policy.
- `workspace/files` is agent-managed durable filesystem state for scratchpads, progress, notes, todos, preferences, and subagent outputs.
- `workspace/artifacts` is runtime-managed tool-output storage for offloaded results.
- `core/tools` should stay focused on generic tool execution and registry plumbing, not workspace storage.
- Runtime binds the offloader to the same workspace object when workspace-file tools are prepared.

## Current System Prompt PR Notes

Branch: `cleanup/system-prompts`

Direction:
- Replace the 1,385-line `core/system_prompts.py` file with a focused
  `core/system_prompts/` package.
- Keep one prompt ownership area instead of scattering prompt text across
  agents, runtime, tools, or workspace modules.
- Preserve current prompt behavior unless we deliberately redesign prompt
  contracts later.

New ownership:
- `core/system_prompts/__init__.py`: public prompt API exports.
- `core/system_prompts/builder.py`: `OmniCoreAgentPromptBuilder` and
  `AgentPromptContextBuilder`.
- `core/system_prompts/base.py`: base ReAct prompt.
- `core/system_prompts/extensions.py`: optional harness extension prompt blocks
  for subagents, tool retrieval, workspace files, artifacts, and skills.
- `core/system_prompts/summaries.py`: conversation and memory summarization
  prompts.

Notes:
- Direct configured sub-agents and dynamic spawned subagents are both still real
  surfaces in code, but the prompt should not teach them as two competing
  systems.
- `sub_agents_additional_prompt` and `dynamic_subagents_additional_prompt` were
  collapsed into one `build_subagents_additional_prompt` harness builder.
- `spawn_subagents` is now the primary path for natural delegated execution.
- The configured sub-agent registry remains a smaller explicit worker path when
  an application passes sub-agents directly.
- The subagent prompt builder only mentions `spawn_subagents` when
  `enable_subagents` is active, so prompt guidance matches the tool surface.
- Lower-level agent, prompt, and tool-registry constructors also treat dynamic
  subagents as requiring workspace-file tools, matching `AgentConfig`.
- Prompt examples were audited against the actual XML parser. Examples now use
  parser-supported `<tool_call>` / `<tool_calls>` shapes instead of custom
  tags such as `<tool_call_1>` or JSON-only parameter examples.
- Removed stale observation-marker prompt text that did not match the runtime
  observation format.
- Message history loading now skips persisted configured-subagent observation
  blocks the same way it skips normal tool observation blocks, keeping new
  requests clean after prior delegated work.
