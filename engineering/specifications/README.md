# Specifications

Specifications define exact behavior that implementation and tests must satisfy.

A specification should answer:

- what configuration fields exist
- which values are valid
- what public or internal tools accept
- what each operation returns
- what errors are expected
- how local and cloud behavior must match
- which tests prove the contract

Specifications are stricter than architecture records. Architecture explains
the system shape and decisions. A specification defines the contract that code
must obey.
