# Quickstart

In five minutes you will have an agent that calls a Python function as a tool,
remembers a conversation, and leaves a record of every step it took — which you
will read back.

<Info>
About five minutes, and a fraction of a cent of model usage. Every output on this
page is what the code printed when it was run; the model's wording will differ on
your run.
</Info>

<Steps>
  <Step title="Install">
    ```bash
    pip install omnicoreagent
    ```

    The core install is light. Databases, sandboxes, the server and the rest come
    as [extras](/docs/getting-started/installation), when you need them.
  </Step>

  <Step title="Set your model key">
    ```bash
    export LLM_API_KEY=your_api_key_here
    ```

    <Tip>
    `LLM_API_KEY` is the one key variable, whichever provider you use; the
    provider is chosen in `model_config`. See [Models](/docs/how-to-guides/models)
    for the providers and their names.
    </Tip>
  </Step>

  <Step title="Your first agent">
    Save this as `hello_agent.py` and run `python hello_agent.py`:

    ```python
    import asyncio
    from omnicoreagent import OmniCoreAgent

    async def main():
        agent = OmniCoreAgent(
            name="my_agent",
            system_instruction="You are a helpful assistant.",
            model_config={"provider": "openai", "model": "gpt-5.6-terra"},
        )
        result = await agent.run("Hello! In one sentence, what can you do?")
        print(result["response"])
        await agent.cleanup()

    asyncio.run(main())
    ```

    ```text
    I can answer questions, research and analyze information, create or edit workspace files, and help plan, write, troubleshoot, and complete tasks accurately.
    ```

    `result` is a dictionary; which keys it has depends on how the run ended:

    | Key | When | What |
    |---|---|---|
    | `response` | always | the agent's answer, or why it stopped |
    | `status` | always | `success`, `error`, `awaiting_approval`, `awaiting_budget`, `interrupted`, or `blocked` (the guardrail refused the input) |
    | `run_id`, `session_id`, `trace_id` | always | where to find this run again |
    | `metric` | finished | token usage (a `Usage`: `requests`, `request_tokens`, `response_tokens`, `total_tokens`, `total_time`) |
    | `termination_reason` | finished | why it stopped: `stop`, `max_steps`, `provider_error`, … |
    | `approvals` | `awaiting_approval` | each call waiting for a person ([tour](/docs/getting-started/tour)) |
    | `budget_request` | `awaiting_budget` | what the run needs to carry on |

    The run's **cost in dollars** is in its trajectory, next step:
    `trajectory["totals"]["estimated_cost_usd"]`.
  </Step>

  <Step title="Give it a tool">
    A tool is a Python function with type hints and a docstring. The model
    decides when to call it.

    ```python
    import asyncio
    from omnicoreagent import OmniCoreAgent, ToolRegistry

    tools = ToolRegistry()

    @tools.register_tool("get_weather")
    def get_weather(city: str) -> dict:
        """Get current weather for a city."""
        return {"city": city, "temp": "22C", "condition": "Sunny"}

    async def main():
        agent = OmniCoreAgent(
            name="weather_agent",
            system_instruction="Use tools when they help answer the user. Answer in plain text.",
            model_config={"provider": "openai", "model": "gpt-5.6-terra"},
            local_tools=tools,
        )
        result = await agent.run("What's the weather in Tokyo?")
        print(result["response"])

        trajectory = await agent.get_trajectory(result["trace_id"])
        for step in trajectory["steps"]:
            for call in step["tool_calls"]:
                print("step", step["step"], "->", call["tool_name"], call["arguments"], call["outcome"])
        print("totals:", {k: trajectory["totals"].get(k) for k in ("steps", "tokens", "estimated_cost_usd")})

        await agent.cleanup()

    asyncio.run(main())
    ```

    ```text
    Tokyo is currently sunny, with a temperature of 22°C.
    step 1 -> get_weather {'city': 'Tokyo'} success
    totals: {'steps': 2, 'tokens': {'input': 3017, 'output': 35, 'total': 3052, 'cached_input': 1466, 'reasoning': 0}, 'estimated_cost_usd': 0.0045877}
    ```

    The last lines are the run's **trajectory**: every step, the tool the model
    called, the arguments it chose, how the call ended, and what the run cost.
    Every run keeps one. [Everything in a trajectory](/docs/how-to-guides/observability#read-a-run-as-a-trajectory)
    — including exactly what the model was sent and what each tool returned —
    is on the Observability page.
  </Step>

  <Step title="Remember a conversation">
    Runs with the same `session_id` share their history. A different one starts
    fresh.

    ```python
    await agent.run("My name is Ada and I like short answers.", session_id="user_123")
    result = await agent.run("What is my name?", session_id="user_123")
    print(result["response"])

    other = await agent.run("What is my name?", session_id="someone_else")
    print(other["response"])
    ```

    ```text
    Ada.
    I don’t know your name—you haven’t told me.
    ```

    History lives in memory by default. To keep it across restarts, use Redis,
    Postgres or MongoDB ([Memory](/docs/core-concepts/memory)).
  </Step>
</Steps>

## What you just used

Without asking for any of it, that agent ran the runtime's loop — the model
calling tools, independent calls in one batch, results as structured
observations — with session memory, a workspace for files, the prompt-injection
guardrail, and a full record of the run.

You will find a `workspace/` folder where you ran the script: the agent's files
(`files/`), large tool results saved for the agent to read back (`artifacts/`),
and the record of every run (`telemetry/`). To keep it elsewhere, set
`agent_config={"workspace_config": {"workspace_dir": "/path/to/workspace"}}`. Everything else is switched on when you
want it: a policy over what the agent may do, a sandbox for commands, budgets,
background runs, a server.

## When things go wrong

These are the messages you will actually see.

<AccordionGroup>
  <Accordion title="ValueError: LLM_API_KEY not found in environment variables">
    The key is not set in the shell that runs the script:

    ```bash
    export LLM_API_KEY=your_api_key_here
    ```

    The runtime does not read `.env` files itself. If your key is in one, load it
    at the top of your script:

    ```python
    from dotenv import load_dotenv

    load_dotenv()
    ```
  </Accordion>

  <Accordion title="ValueError: model_config.provider is required">
    Name both the provider and the model:

    ```python
    model_config = {"provider": "openai", "model": "gpt-5.6-terra"}
    ```
  </Accordion>

  <Accordion title="The model call was refused: the provider does not serve the model … to this account">
    The run ends with `status` `"error"` and this message when the model name is
    wrong, or your account cannot use that model:

    ```text
    The model call was refused: the provider does not serve the model `gpt-does-not-exist` to this account; check model_config's model name and provider. Retrying will not help.
    ```

    Check the spelling against your provider's model list, and that
    `model_config["provider"]` is the provider that serves it.
  </Accordion>
</AccordionGroup>
