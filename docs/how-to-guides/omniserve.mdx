# OmniServe

OmniServe puts one agent behind an HTTP API: a run as JSON or as a live
stream, the run's record and trajectory afterwards, a person's approval
mid-run, and background tasks, with auth, rate limits and a request timeout.
One command, `omniserve run --agent my_agent.py`, or `OmniServe(agent).start()`
in your own script.

<Info>
Every output on this page is what the server returned when it was run. The
model's wording, the ids and the timings will differ on your run. Each
route's fields are in the generated [HTTP API reference](/docs/reference/openapi.json),
under **HTTP API (OmniServe)** in the navigation.
</Info>

```bash
pip install "omnicoreagent[serve]"
export LLM_API_KEY=...   # your model provider's key
```

## Serve an agent

Save this as `my_agent.py`. OmniServe takes the module's `agent`, or calls
its `create_agent()` when there is no `agent`:

```python
from omnicoreagent import OmniCoreAgent, ToolRegistry

tools = ToolRegistry()

@tools.register_tool("get_order")
def get_order(order_id: str) -> dict:
    """Look up an order by its id."""
    return {"order_id": order_id, "status": "shipped", "total": 42.0}

agent = OmniCoreAgent(
    name="support",
    system_instruction="You answer questions about orders. Answer in plain text, in one sentence.",
    model_config={"provider": "openai", "model": "gpt-5.4-mini"},
    local_tools=tools,
)
```

Serve it (on port 8771 here; the default is 8000):

```bash
omniserve run --agent my_agent.py --port 8771
```

## Stream a run

`POST /run` takes the same body and answers with Server-Sent Events: the
run's telemetry as it happens, the answer as it is written (`text_delta`),
and a final `complete` with the same fields as `/run/sync`. A small client:

```python
import json
import httpx

body = {
    "query": "Where is order 1042, and what did it cost? Save a one-line note about it in notes.txt.",
    "session_id": "dave",
}
with httpx.stream("POST", "http://localhost:8771/run", json=body, timeout=None) as response:
    event = None
    for line in response.iter_lines():
        if line.startswith("event: "):
            event = line.removeprefix("event: ")
        elif line.startswith("data: "):
            data = json.loads(line.removeprefix("data: "))
            if event == "text_delta":
                print(data["text"], end="", flush=True)
            elif event == "tool_requested":  # every tool: yours, workspace, MCP
                print(f"[tool_requested] {data['input']['tool_name']} {data['input']['arguments']}")
            elif event == "tool_result":  # what one of your own tools returned
                print(f"[tool_result] {data['output']['status']} {data['output']['data']}")
            elif event in ("workspace_read", "workspace_write"):  # a workspace file tool
                print(f"[{event}] {data['output']['status']} {data['input']['tool_args']['path']}")
            elif event == "tool_observation":  # the result as the model was given it
                print(f"[tool_observation] {data['output']['tool_name']}")
            elif event == "complete":
                print(f"\n[complete] {data['status']} {data['run_id']}")
            elif event == "error":
                print(f"[error] {data['error']}")
```

```text
[tool_requested] get_order {'order_id': '1042'}
[tool_result] success {'order_id': '1042', 'status': 'shipped', 'total': 42.0}
[tool_observation] get_order
[tool_requested] write_file {'path': 'notes.txt', 'content': 'Order 1042 is shipped and cost $42.00.\n', 'mode': 'create'}
[workspace_write] success notes.txt
[tool_observation] write_file
Order 1042 is shipped and cost $42.00, and I saved a one-line note in notes.txt.
[complete] success run_c9fad249e7734f1aae948066a2b5f9a9
```

Every tool call, whatever its kind, arrives as `tool_requested` and ends with
`tool_observation`. What ran in between is named by its kind: `tool_call` and
`tool_result` for your own tools, `workspace_read` and `workspace_write` for the
workspace file tools. A client that listens only for `tool_result` misses every
file the agent reads or writes.

A stream always opens with `event: session` (`"status": "started"`) and
closes with `event: session` (`"status": "ended"`). In between, for a run
with no tool call, `curl -N` saw these events, in order:

```text
session user_message guardrail_check memory_read run_configuration runtime_message
memory_write agent_step context_assembly context_message (x2) context_tools model_call
text_delta (x7) model_response memory_write final_answer complete session
```

- `text_delta` is live only: it is never stored, so a replay does not have it.
- Check `status` on `complete` before treating the run as a success
  (it can be `error`, `awaiting_approval` or `awaiting_budget`).
- A failure arrives as `event: error` with `error`, `session_id` and `run_id`.
- Closing the connection cancels the run, whatever the request timeout
  ([below](#the-request-timeout)).

## A person in the loop

With [governance](/docs/core-concepts/policies) on, a rule that says `ask`
pauses the run and `/run/sync` returns `awaiting_approval`. This agent
(`refund_agent.py`) asks before any refund, and has a slow report tool:

```python
import asyncio

from omnicoreagent import OmniCoreAgent, ToolRegistry

tools = ToolRegistry()

@tools.register_tool("get_order")
def get_order(order_id: str) -> dict:
    """Look up an order by its id."""
    return {"order_id": order_id, "status": "shipped", "total": 42.0}

@tools.register_tool("issue_refund")
def issue_refund(order_id: str, amount: float) -> dict:
    """Refund an order."""
    return {"order_id": order_id, "refunded": amount}

@tools.register_tool("build_report")
async def build_report() -> str:
    """Build the daily orders report. It is slow."""
    await asyncio.sleep(30)
    return "12 orders shipped, 1 refunded."

policy = {
    "name": "support-desk",
    "mode": "strict",
    "rules": {
        "allow": [
            {"rule_id": "tools", "capability": "tool.local.call"},
            {"rule_id": "tasks", "capability": "background.task.create"},
            {"rule_id": "runs", "capability": "background.run.start"},
        ],
        "ask": [
            {
                "rule_id": "refunds",
                "capability": "tool.local.call",
                "target": {"tool_name": "issue_refund"},
                "reason": "Refunds need a person.",
            }
        ],
    },
}

agent = OmniCoreAgent(
    name="support",
    system_instruction="You answer questions about orders and refund when asked. Answer in plain text, in one sentence.",
    model_config={"provider": "openai", "model": "gpt-5.4-mini"},
    local_tools=tools,
    agent_config={"governance_config": {"enabled": True, "policy": policy}},
)
```

then resume. A running run can be steered (`POST /runs/{run_id}/steer`,
`{"message": "..."}`) or stopped at its next step (`POST /runs/{run_id}/interrupt`,
then resume); see [Durable runs](/docs/core-concepts/durable-runs).

## Background tasks

The served agent is registered for [background runs](/docs/core-concepts/background-agents)
at startup, as agent `default`. On the same server:

```bash
curl -s -X POST localhost:8773/background/tasks -H "Content-Type: application/json" \
  -d '{"task_id": "order_check", "query": "Look up order 1042 and say its status.",
       "schedule": {"type": "manual"}, "timeout_seconds": 120}'
curl -s -X POST localhost:8773/background/tasks/order_check/run \
  -H "Content-Type: application/json" -d '{"wait": true}'
```

The second call waited for the run and returned it (abridged):

```text
{"run_id":"run_03ff6252cd7a40fba069ee9f1af2ef7f","task_id":"order_check","agent_id":"default","status":"completed","attempt":1,"max_attempts":1,"query_snapshot":"Look up order 1042 and say its status.","trigger_type":"manual",...,"session_id":"background:default:order_check","workspace_path":"background/default/order_check/run_03ff6252cd7a40fba069ee9f1af2ef7f",...,"error":null,"result_preview":"Order 1042 is shipped.",...}
```

With `{"wait": false}` (the default) it returns the queued run at once. A
schedule is `manual`, `once`, `interval` or `cron`. Then:

```bash
curl -s localhost:8773/background/status
curl -s localhost:8773/background/tasks/order_check/status
curl -s localhost:8773/background/runs/$RUN_ID
curl -s localhost:8773/background/runs/$RUN_ID/events
curl -s localhost:8773/background/runs/$RUN_ID/workspace
```

```text
{"running":true,"initialized":true,"worker_id":"worker_e8ad38bf0ef340cba2b7150683e4c681","lease_seconds":30.0,"agents":1,"tasks":1,"runs":1,"active_runs":0,"status_counts":{"queued":0,"claimed":0,"running":0,"retrying":0,"completed":1,"failed":0,"cancelled":0,"timeout":0,"skipped":0,"awaiting_approval":0,"awaiting_budget":0}}
```

The run's events were `background_run_queued`, `background_run_claimed`,
`background_run_started`, `background_run_completed`; while a run is running
it also records a `background_run_heartbeat` at intervals (a longer run has
several). Its workspace held
`run.json` and `events.jsonl`.

Under governance the agent's policy also decides what an operator asks here:
creating, changing, pausing, resuming or deleting a task is
`background.task.<action>`, starting or cancelling a run is
`background.run.<action>`. The policy above allows `create` and `start` only,
so a `DELETE` is refused with a `403` (below). Allow them for the operators
you trust ([policy reference](/docs/reference/policy)).

### A task store that survives restarts

Tasks, runs, attempts, leases and retries live in the background task
store, which is not conversation memory (that stays in the agent's
`MemoryRouter`). The default is in-memory: fine for development, gone on
restart. Pick one backend for a deployment:

- Use SQL for local durability with SQLite, or PostgreSQL or MySQL when several processes share one store.
- Use Redis when your deployment already operates Redis with persistence and no eviction for task-store keys.
- Use MongoDB when MongoDB is your durable operational store (it writes with majority concern).

With a durable store, a queued run survives: OmniServe can queue a run, stop,
start again with the same task store, and the new worker claims and
completes it. The server in the next section kept a cron task across a
restart.

## Serve from your own code

`OmniServe(agent, config=...)` gives you the same server from a script.
`server.py`, with a path prefix, a token and a SQLite task store:

```python
from omnicoreagent import OmniCoreAgent, OmniServe, OmniServeConfig

agent = OmniCoreAgent(
    name="support",
    system_instruction="You answer questions about orders. Answer in plain text, in one sentence.",
    model_config={"provider": "openai", "model": "gpt-5.4-mini"},
)

config = OmniServeConfig(
    port=8776,
    api_prefix="/api/v1",
    auth_enabled=True,
    auth_token="change-me",
    background_task_store="sql",
    background_task_store_url="sqlite:///background.db",
)

if __name__ == "__main__":
    OmniServe(agent, config=config).start()
```

```bash
python server.py
curl -s localhost:8776/api/v1/ready
curl -s localhost:8776/ready
curl -s -X POST localhost:8776/api/v1/background/tasks -H "Authorization: Bearer change-me" \
  -H "Content-Type: application/json" \
  -d '{"task_id": "nightly", "query": "Summarise the day in one sentence.", "schedule": {"type": "cron", "expression": "0 2 * * *"}}'
# stop the server, start it again, then:
curl -s localhost:8776/api/v1/background/tasks/nightly/status -H "Authorization: Bearer change-me"
```

```text
{"ready":true,"agent_name":"support","initialized":true,"mcp_connected":true,"mcp_servers":{}}
{"detail":"Not Found"}
nightly 0 2 * * * 2026-09-28T02:00:00Z
```

(The last line is the status's `task_id`, `schedule.expression` and
`schedule_state.next_due_at`, after the restart.) The prefix moves the
agent's routes; `/docs`, `/redoc`, `/openapi.json` and `/prometheus` stay at
the root. `server.start()` blocks; `await server.start_async()` runs inside
your event loop, and `server.get_app()` returns the FastAPI app to mount
elsewhere or test.

<Warning>
`OMNICOREAGENT_SERVE_*` and `OMNICOREAGENT_BACKGROUND_*` environment
variables always override what the code or the CLI flags set. A stray
`OMNICOREAGENT_SERVE_PORT` in the environment wins over `port=8776`.
</Warning>

### Your own routes beside the agent's

The agent file (or `OmniServe(..., routers=[...], public_paths=[...])`) can
add an application's own pages and endpoints, served on the same origin
behind the same middleware:

```python
from fastapi import APIRouter
from fastapi.responses import HTMLResponse

router = APIRouter()            # or routers = [...]

@router.get("/steward/", response_class=HTMLResponse)
async def page() -> str:
    return open("page.html").read()

public_paths = ["/steward/"]    # served without a token; "/steward/*" for a directory
```

Everything else these routers serve needs the bearer token when auth is on.
[apps/steward](https://github.com/omnirexflora-labs/omnicoreagent/tree/main/apps/steward)
is a complete application served this way.

## How it works

<Steps>
  <Step title="Startup">
    The server connects the agent's MCP servers, warms the model client,
    starts the background manager (registering the agent as `default`) and
    its worker. The server answers no request, `/health` included, until
    startup has finished, which can take up to a minute on a busy machine.
    After that, `/health` says the process is up, and `/ready` says `true`
    while the agent is initialized and its MCP servers are connected.
  </Step>
  <Step title="Each request">
    Middleware, outermost first: CORS, request logging, the rate limit, the
    bearer token, the request timeout, and a last catch that turns an
    uncaught error into a JSON `500`. A policy refusal becomes a `403`.
  </Step>
  <Step title="A run">
    `/run/sync` and `/run` call `agent.run(...)` with the session and a new
    `run_id`, and record a request trace next to the agent's own. The run
    is durable like any other: its record lives in the agent's memory store
    and its traces under the workspace (`./workspace/telemetry/`).
  </Step>
  <Step title="Shutdown">
    The background manager stops, then `agent.cleanup()` closes its
    connections.
  </Step>
</Steps>

One server process serves one agent instance, so `workers` must be `1`.
To scale, run several processes (or containers) behind a load balancer,
sharing a durable memory store and task store; the rate limit is counted per
process. [Stores and scale](/docs/how-to-guides/stores-and-scale) has the
details.

## Routes

Every route, its body and its response fields are in the
[HTTP API reference](/docs/reference/openapi.json). Paths below are relative
to `api_prefix` (empty by default).

### Runs

| Method | Route | What it does |
|--------|-------|--------------|
| `POST` | `/run/sync` | Run and wait; the result as JSON |
| `POST` | `/run` | Run and stream SSE events, ending with `complete` |
| `GET` | `/runs` | Runs by `status` and `session_id`, oldest first (`limit`, up to 500): what waits for a person, what a crash left `running` (its `heartbeat_at` and `lease_seconds` say whether it is still alive; `attempt` which try it is). An unknown status is `422`. The answer is `{"runs": [...]}`, each as `GET /runs/{run_id}` returns it; a `running` run whose `heartbeat_at` is older than `lease_seconds` has no live process |
| `GET` | `/runs/{run_id}` | The run's record: status, step, usage, tool call states, approvals (never its conversation) |
| `GET` | `/runs/{run_id}/trajectory` | The whole run as one story: every trace segment, totals, each tool call once, the approvals |
| `POST` | `/runs/{run_id}/approvals/{approval_id}` | Decide an approval: `{"decision": "approve" \| "deny", "approver", "note"?, "arguments"?}` |
| `POST` | `/runs/{run_id}/resume` | Continue a paused or interrupted run once it is decided |
| `GET` | `/runs/{run_id}/budget` | Every budget covering the run, and each time it ran out |
| `POST` | `/runs/{run_id}/budget` | Grant or refuse: `{"decision": "grant" \| "deny", "approver", "amount"?, "note"?}` |
| `POST` | `/runs/{run_id}/steer` | A message for the run's next step: `{"message", "sender"?}` |
| `POST` | `/runs/{run_id}/interrupt` | Stop the run at its next step boundary; resume continues it |
| `POST` | `/runs/{run_id}/outcome` | What the run turned out to be worth: `{"source", "reward"?, "label"?, "detail"?}` |

## Authentication

Off by default. Turn it on with a token:

```bash
omniserve run --agent my_agent.py --auth-token s3cret-token
# or
export OMNICOREAGENT_SERVE_AUTH_ENABLED=true
export OMNICOREAGENT_SERVE_AUTH_TOKEN=s3cret-token
```

Then every route but `/health`, `/ready`, `/prometheus`, `/docs`, `/redoc`,
`/openapi.json` and your `public_paths` needs the header:

```bash
curl -s localhost:8774/tools -H "Authorization: Bearer s3cret-token"
```

There is one token per server; for per-user identity, put OmniServe behind a
gateway that authenticates users. CORS is open (`*`) by default; set
`OMNICOREAGENT_SERVE_CORS_ORIGINS` to your front end's origin.

## Configuration

Flags on `omniserve run`: `--agent`, `--host`, `--port`, `--workers` (must
be 1), `--auth-token`, `--rate-limit N` (requests per minute per client IP),
`--cors-origins`, `--no-docs`. Everything else is an environment variable
or an `OmniServeConfig` field of the same name, lower-cased without the
prefix (`OMNICOREAGENT_SERVE_REQUEST_TIMEOUT` is `request_timeout`). With
none set, the defaults serve on `0.0.0.0:8000` with no auth, and the
background API and its worker run with an in-memory task store.

| Variable | Default | What it does |
|----------|---------|--------------|
| `OMNICOREAGENT_SERVE_HOST` | `0.0.0.0` | Host to bind; must not be empty |
| `OMNICOREAGENT_SERVE_PORT` | `8000` | Port, `1`-`65535` |
| `OMNICOREAGENT_SERVE_WORKERS` | `1` | Must be `1`; scale with more processes |
| `OMNICOREAGENT_SERVE_API_PREFIX` | `""` | Prefix for the agent's routes, e.g. `/api/v1` (a leading slash is added, a trailing one removed; no whitespace) |
| `OMNICOREAGENT_SERVE_ENABLE_DOCS` | `true` | Swagger UI at `/docs` |
| `OMNICOREAGENT_SERVE_ENABLE_REDOC` | `true` | ReDoc at `/redoc` |
| `OMNICOREAGENT_SERVE_CORS_ENABLED` | `true` | CORS middleware |
| `OMNICOREAGENT_SERVE_CORS_ORIGINS` | `*` | Allowed origins, comma-separated |
| `OMNICOREAGENT_SERVE_CORS_METHODS` | `*` | Allowed methods, comma-separated |
| `OMNICOREAGENT_SERVE_CORS_HEADERS` | `*` | Allowed headers, comma-separated |
| `OMNICOREAGENT_SERVE_CORS_CREDENTIALS` | `true` | Allow credentials |
| `OMNICOREAGENT_SERVE_AUTH_ENABLED` | `false` | Bearer-token auth; needs a token |
| `OMNICOREAGENT_SERVE_AUTH_TOKEN` | — | The token |
| `OMNICOREAGENT_SERVE_RATE_LIMIT_ENABLED` | `false` | Rate limit per client IP (`X-Forwarded-For` first) |
| `OMNICOREAGENT_SERVE_RATE_LIMIT_REQUESTS` | `100` | Requests per window, at least `1` |
| `OMNICOREAGENT_SERVE_RATE_LIMIT_WINDOW` | `60` | Window in seconds, at least `1` |
| `OMNICOREAGENT_SERVE_REQUEST_LOGGING` | `true` | Log each request; adds `X-Process-Time` |
| `OMNICOREAGENT_SERVE_LOG_LEVEL` | `INFO` | `CRITICAL`, `ERROR`, `WARNING`, `INFO`, `DEBUG` or `TRACE` |
| `OMNICOREAGENT_SERVE_REQUEST_TIMEOUT` | `300` | Seconds a request may take; `0` turns it off |
| `OMNICOREAGENT_BACKGROUND_ENABLED` | `true` | Mount the background routes |
| `OMNICOREAGENT_BACKGROUND_AGENT_ID` | `default` | The served agent's background id |
| `OMNICOREAGENT_BACKGROUND_START_WORKER` | `true` | Run the scheduler and worker in this process |
| `OMNICOREAGENT_BACKGROUND_TASK_STORE` | `in_memory` | `in_memory`, `sql`, `redis` or `mongodb` |
| `OMNICOREAGENT_BACKGROUND_TASK_STORE_URL` | — | SQL or Redis URL (a URL alone means SQL) |
| `OMNICOREAGENT_BACKGROUND_TASK_STORE_URI` | — | MongoDB URI |

A durable task store; pick one backend:

```bash
export OMNICOREAGENT_BACKGROUND_TASK_STORE=sql
export OMNICOREAGENT_BACKGROUND_TASK_STORE_URL=sqlite:///.omnicoreagent/background.db
```

```bash
export OMNICOREAGENT_BACKGROUND_TASK_STORE=redis
export OMNICOREAGENT_BACKGROUND_TASK_STORE_URL=redis://localhost:6379/0
```

```bash
export OMNICOREAGENT_BACKGROUND_TASK_STORE=mongodb
export OMNICOREAGENT_BACKGROUND_TASK_STORE_URI=mongodb://localhost:27017
export OMNICOREAGENT_BACKGROUND_TASK_STORE_DATABASE=omnicoreagent
```

SQL needs `omnicoreagent[postgres]` (SQLAlchemy, for SQLite too), Redis
`omnicoreagent[redis]`, MongoDB `omnicoreagent[mongodb]`. `omniserve config
--show` prints the configuration the environment gives;
`omniserve config --env-example` prints a template. Every option is in the
[CLI reference](/docs/reference/cli) and [configuration](/docs/how-to-guides/configuration).

### The request timeout

`OMNICOREAGENT_SERVE_REQUEST_TIMEOUT` (300 seconds) bounds each request:

- `/run/sync` and `/runs/{run_id}/resume` answer `504` when the run takes
  longer. The run is stopped; its record and trace remain.
- `/run` (SSE) sends `event: error` with `"error": "Request timed out"`
  and closes the stream.
- `/background/tasks/{task_id}/run` with `"wait": true` waits a little less
  than the timeout, then answers `504` with the `run_id`. The run is **not**
  stopped: it carries on in the background. A run that pauses for a person or
  a budget is answered at once, `200` with `awaiting_approval` or
  `awaiting_budget`.

For work longer than a request should last, use a background task.

## Deploy with Docker

```bash
omniserve generate-dockerfile --file my_agent.py
docker build -t omnicoreagent-serve .
docker run -p 8000:8000 -e LLM_API_KEY omnicoreagent-serve
```

It also writes a `.dockerignore` in the directory you run it from (the build
context), if there is none, that
keeps every `.env` and workspace folder, in any subfolder, out of the image
(the image copies the build context); an existing one that does not exclude
`**/.env` is named. The
generated Dockerfile installs `omnicoreagent[serve]`, pinned to the
release that generated it (`==0.5.0`), on
`python:3.12-slim`, copies the build context to `/app`, runs as a non-root
user, checks `/health`, and keeps the workspace in `/tmp/workspace` (gone
with the container unless you mount a volume). Its `HEALTHCHECK` allows a
start period of 10 seconds (`--start-period=10s`); a slow host may need
longer before `/health` first answers, so raise it in the Dockerfile or with
`docker run --health-start-period=60s`. Add the extras your agent
needs (`[serve,postgres]` for a SQL memory store): a comment above the
install line in the Dockerfile says so. A persistent volume, a
store for runs and readiness checks are on
[Running the agent in a container](/docs/how-to-guides/agent-in-a-container).

## When things go wrong

<AccordionGroup>
  <Accordion title="401 Missing or invalid Authorization header">
    Auth is on and the request had no `Authorization: Bearer ...` header, or
    the wrong token:

    ```text
    {"error":"Unauthorized","message":"Missing or invalid Authorization header"}
    {"error":"Unauthorized","message":"Invalid authentication token"}
    ```
  </Accordion>

  <Accordion title="403 Denied by strict policy">
    The agent's policy refused what the request asked, here a task `DELETE`
    the policy does not allow:

    ```text
    {"error":"UnknownCapabilityError","detail":"Denied by strict policy: no rule matches this background.task.delete request.","capability":"background.task.delete","reason_code":"unknown_capability","matched_rule_ids":[]}
    ```

    The body names the refused `capability`, the `reason_code` and the
    `matched_rule_ids` (none here: no rule matched). Add an allow rule for
    that capability (`background.task.delete`), for the operators you trust.

    An `ask` nobody can answer inside the request is refused the same way,
    and the body names the capability and the rule. Under `interactive-dev`,
    every background request asks:

    ```text
    {"error":"ApprovalRequiredError","detail":"Matched ask policy rule.","capability":"background.task.create","reason_code":"approval_required","matched_rule_ids":["ask_background_execution"]}
    ```

    An ask outranks an allow, and `interactive-dev` asks about anything no
    rule matches: for an agent served to operators you trust, take the ask
    rule out and allow the capability.

    ```python
    from omnicoreagent.governance import PolicyEffect, PolicyRule, build_default_policy

    policy = build_default_policy("interactive-dev")
    policy.rules.ask = [r for r in policy.rules.ask if r.rule_id != "ask_background_execution"]
    policy.rules.allow.append(
        PolicyRule(rule_id="operators_run_background", effect=PolicyEffect.ALLOW, capability="background.*")
    )
    ```

    With both, `POST /background/tasks` returns `200`.
  </Accordion>

  <Accordion title="404 No run / Task not found">
    ```text
    {"detail":"No run run_nope"}
    {"detail":"No approval approval_nope on run run_192cf4b607f641cd9f7431befc89b93f"}
    {"detail":"Task not found: nope"}
    ```

    A run's record lives in the agent's memory store: with the default
    in-memory store, a restart forgets every run. Use a durable
    [memory store](/docs/core-concepts/memory).
  </Accordion>

  <Accordion title="409 still waiting, already decided, already finished">
    The request does not fit the run's state:

    ```text
    {"detail":"Run run_192cf4b607f641cd9f7431befc89b93f is still waiting for approval: approval_1db56482b7db412b96e07776776d86b4"}
    {"detail":"Approval approval_1db56482b7db412b96e07776776d86b4 is already approved"}
    {"detail":"Approval approval_1db56482b7db412b96e07776776d86b4 is already used"}
    {"detail":"Run run_192cf4b607f641cd9f7431befc89b93f is completed; only a waiting or stopped run can resume"}
    {"detail":"Task already registered: order_check"}
    ```

    An approval reads `already approved` (or `denied`) once decided, and
    `already used` once a resume has applied the decision. Decide every
    approval before resuming; send `"replace": true` to
    overwrite a task.
  </Accordion>

  <Accordion title="422 a body that does not validate">
    ```text
    {"detail":[{"type":"literal_error","loc":["body","decision"],"msg":"Input should be 'approve' or 'deny'","input":"maybe","ctx":{"expected":"'approve' or 'deny'"}}]}
    ```

    `/runs/{run_id}/steer` also answers `422` when the injection guardrail
    blocks the message.
  </Accordion>

  <Accordion title="429 Rate limit exceeded">
    With `--rate-limit 3`, the fourth request in a minute:

    ```text
    HTTP/1.1 429 Too Many Requests
    x-ratelimit-limit: 3
    x-ratelimit-remaining: 0
    x-ratelimit-reset: 1790550444
    retry-after: 59
    {"error":"TooManyRequests","message":"Rate limit exceeded. Max 3 requests per 60 seconds.","retry_after":59}
    ```

    Every request but the public paths counts, rejected ones (a `401`)
    included.
  </Accordion>

  <Accordion title="504 Request timed out">
    A `/run/sync` under a 1-second timeout, with a model slower than that:

    ```text
    {"detail":{"message":"Request timed out after 1 seconds","run_id":"run_bb48117c442e48c0b63efaa7beee4b4a","session_id":"omni_core_agent_slow_ceb1792e","request_timeout_seconds":1}}
    ```

    The run is stopped and its record says `timeout`
    (`GET /runs/{run_id}`); the `run_id` finds its trajectory. `POST
    /runs/{run_id}/resume` answers a timeout the same way.

    A background run waited on with `"wait": true`:

    ```text
    {"detail":{"message":"Background run did not finish within 18.0 seconds","run_id":"run_9d9ac5f1f756447e856c90b93ebb5e2f","task_id":"daily_report","status":"running","wait_timeout_seconds":18.0,"request_timeout_seconds":20}}
    ```

    That run finished later (`GET /background/runs/{run_id}` said
    `completed`). Raise `OMNICOREAGENT_SERVE_REQUEST_TIMEOUT`, or queue long
    work without waiting.
  </Accordion>

  <Accordion title="The server will not start: Invalid OmniServe config">
    The configuration is checked before the agent is loaded:

    ```text
    Error: Invalid OmniServe config: 1 validation error for OmniServeConfig
      Value error, OMNICOREAGENT_SERVE_AUTH_TOKEN is required when OMNICOREAGENT_SERVE_AUTH_ENABLED=true [type=value_error, ...]
    Error: Invalid OmniServe config: 1 validation error for OmniServeConfig
      Value error, OMNICOREAGENT_SERVE_WORKERS must be 1 for direct OmniServe. Run multiple OmniServe processes behind a process manager for horizontal scaling. [type=value_error, ...]
    ```

    A Redis or MongoDB task store without its address is refused the same
    way: `Error: Invalid OmniServe config: Redis background task store
    requires OMNICOREAGENT_BACKGROUND_TASK_STORE_URL` (`..._URI` for
    MongoDB).
  </Accordion>

  <Accordion title="Agent file must define an 'agent' variable or 'create_agent()' function">
    ```text
    Error: Agent file must define an 'agent' variable or 'create_agent()' function
    Error: Invalid value for '--agent' / '-a': Path 'missing.py' does not exist.
    ```

    An exception while importing the file is reported as
    `Error loading agent file: ...`.
  </Accordion>

  <Accordion title="Application startup failed: LLM_API_KEY not found">
    The model key is read when the agent is built; without it the server
    exits:

    ```text
    ValueError: LLM_API_KEY not found in environment variables

    ERROR:    Application startup failed. Exiting.
    ```

    Set `LLM_API_KEY` in the server's environment. A key the provider
    rejects starts fine, and each run ends with `status` `error`,
    `termination_reason` `provider_error`.
  </Accordion>

  <Accordion title="OmniServe cannot listen on host:port: it is in use">
    Another process holds the port. The port is checked before the agent is
    loaded, so this comes at once:

    ```text
    Error: OmniServe cannot listen on 0.0.0.0:8771: it is in use or not available (Address already in use); choose another port
    ```

    Pick another `--port`, or stop what holds it.
  </Accordion>
</AccordionGroup>
