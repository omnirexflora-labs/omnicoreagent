# Prompt Injection Guardrails

Protect your agents against malicious inputs, jailbreaks, and instruction overrides before they reach the LLM.

```python
agent_config = {
        "guardrail_config": {
            "strict_mode": True,      # Block all suspicious inputs
            "sensitivity": 1.2,       # 1.0 default; higher = more sensitive
            "enable_heuristic_analysis": True
        }
}

agent = OmniCoreAgent(..., agent_config=agent_config)

# If a threat is detected:
# result['response'] -> "I'm sorry, but I cannot process this request..."
# result['guardrail_result'] -> Full metadata about the detected threat
```

Guardrail enforcement is selected with `agent_config["guardrail_mode"]`:

| Mode | User input | Tool output | Default |
|------|------------|-------------|---------|
| `full` | checked and unsafe input is blocked | suspicious output follows `suspicious_output_action`; dangerous/critical output is always blocked | Yes |
| `input_only` | checked and unsafe input is blocked | not checked by the agent runtime | No |
| `off` | not checked | not checked | No |

The mode is validated when the public agent configuration is built. Unknown
values fail before a model connection or tool can be constructed. `strict_mode`
changes the detection thresholds; low-risk results remain allowed, while the
input boundary blocks results whose `is_safe` value is false. Detection settings
are validated before runtime construction, including positive finite sensitivity,
positive input length, booleans, logging level, and compilable regular expressions.

---

## Key Protections

- **Instruction Overrides**: "Ignore previous instructions..."
- **Jailbreaks**: DAN mode, roleplay escapes, etc.
- **Toxicity & Abuse**: Built-in pattern recognition.
- **Payload Splitting**: Detects fragmented attack attempts.

---

## Configuration Options

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `strict_mode` | `bool` | `False` | When `True`, lower score thresholds classify suspicious, dangerous, and critical inputs more aggressively. |
| `sensitivity` | `float` | `1.0` | Scaling factor for threat scores. Lower reduces sensitivity; higher increases sensitivity. |
| `max_input_length` | `int` | `10000` | Maximum allowed query length before blocking. |
| `enable_encoding_detection` | `bool` | `True` | Detects base64, hex, and other obfuscation attempts. |
| `enable_heuristic_analysis` | `bool` | `True` | Analyzes prompt structure for typical attack patterns. |
| `enable_sequential_analysis` | `bool` | `True` | Checks for phased attacks across multiple tokens. |
| `enable_entropy_analysis` | `bool` | `True` | Detects high-entropy payloads common in injections. |
| `allowlist_patterns` | `list` | `[]` | List of regex patterns that bypass safety checks. |
| `blocklist_patterns` | `list` | `[]` | Custom regex patterns to always block. |
| `suspicious_output_action` | `"block"` or `"flag"` | `"block"` | Whether suspicious local tool output is blocked before it enters model context or only recorded and passed through. Dangerous and critical output is always blocked. |

<Warning>
Always enable guardrails in user-facing applications to prevent prompt injection attacks and ensure agent reliability.
</Warning>

## Privacy boundaries

The runtime has a separate privacy policy for data that is persisted or exposed
outside the model context. It redacts email addresses, phone numbers, Social
Security numbers, and valid payment card numbers from telemetry, conversation
memory, workspace writes and offloaded artifacts, stream events, and public
results by default. The model keeps the original task content unless
`redact_model_io` is enabled.

Configure it through `agent_config["privacy_config"]`:

```python
agent_config = {
    "privacy_config": {
        "enabled": True,
        "redact_memory": True,
        "redact_workspace": True,
        "redact_telemetry": True,
        "redact_stream": True,
        "redact_public": True,
        "redact_model_io": False,
        "categories": ["email", "phone", "ssn", "credit_card"],
    }
}
```

Each boundary can be disabled deliberately for an integration that has its
own data controls. The effective privacy policy fingerprint is recorded in
telemetry metadata so traces show which policy produced them.
