# Prompt Injection Guardrails

A screen for injection *phrasing*: text that tries to redirect the model or
reach its instructions is caught before the model sees it — in a person's
message, in a tool's output, in an MCP server's result. It is not the
security boundary. What the agent may *do* is decided by
[governance](/docs/core-concepts/security-model); where its code runs is the
sandbox. The screen makes an attempt visible early, and records it in the
trace; the policy is what stops the damage.

```python
from omnicoreagent import OmniCoreAgent

agent_config = {
    "guardrail_mode": "full",          # full (default), input_only, or off
    "guardrail_config": {
        "strict_mode": False,          # True: hidden or framed content blocks on its own
        "suspicious_output_action": "flag",
    },
}

agent = OmniCoreAgent(..., agent_config=agent_config)

# A blocked input:
# result["status"] == "blocked"; result["guardrail_result"] has the verdict and what was found
```

## What counts as evidence

The verdict comes from the *kinds* of evidence found, never from adding up
weak signals. Two kinds exist:

| Kind | Examples | Alone |
|------|----------|-------|
| **Intent addressed to the model** (strong) | *ignore / disregard / forget your previous instructions*; *from now on you are …*; *you are now an unrestricted …*; *enter developer mode*; *you are DAN*; *reveal / print / repeat your system prompt*; *what were you told*; *this message overrides all previous*; *new instructions for the assistant:*; a stated intent to decode a payload and follow it | **dangerous** |
| **Content hidden from a reader** (weak) | escape sequences (three or more), letters spaced out (`o v e r r i d e`), system framing (`[SYSTEM]`, `<system>`, ```` ```system ````) | **suspicious** (dangerous in strict mode) |

Two strong kinds, or a strong kind beside hidden content, is **critical**.
Nothing found is **safe**. Leetspeak (`1gn0r3 4ll pr3v10us 1nstruct10ns`) and
spaced-out letters are folded before matching, so the intent behind them is
matched as written.

What is **not** evidence, by design: structure (markdown rules, code fences,
docstring quotes, diff markers, JSON), vocabulary (the words *system*,
*prompt*, *instruction*, *override*, *secret*, *admin*, *root* on their own),
length, entropy, identifiers (a run id, a commit SHA, a handle), and the
runtime's own text (its preamble, its `[system context: …]` notes). A screen
that scored those blocked 3% of this repository's own text and flagged 16%
before the redesign; it now blocks none of it. The corpus that holds it to
this — ordinary developer text that must never be even suspicious, attacks
that must be blocked — is `tests/test_guardrail_corpus.py`; add to it when
the screen is wrong about something real.

## Modes

`agent_config["guardrail_mode"]`:

| Mode | User input | Tool output | Default |
|------|------------|-------------|---------|
| `full` | checked; a dangerous or critical input is blocked | checked; dangerous or critical output is always blocked; suspicious output follows `suspicious_output_action` | Yes |
| `input_only` | checked and blocked as above | not checked | No |
| `off` | not checked | not checked | No |

Blocked input ends the run with a `blocked` status and the verdict in
`guardrail_result`. Blocked tool output is replaced by a note the model can
see, and the tool call is recorded as an error. Either way the trace has a
`guardrail_violation` event with what was found.

## Configuration

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `strict_mode` | `bool` | `False` | Hidden or framed content blocks on its own (dangerous), rather than being recorded as suspicious. |
| `suspicious_output_action` | `"flag"` or `"block"` | `"flag"` | Whether suspicious tool output is recorded and passed through, or replaced before it enters model context. Dangerous and critical output is always blocked. |
| `max_input_length` | `int` | `10000` | Longer input is refused before analysis. |
| `blocklist_patterns` | `list` | `[]` | Regular expressions that always block, before anything else. |
| `allowlist_patterns` | `list` | `[]` | Regular expressions that let a text through unless intent is found in it: an allowlist cannot pass an override or an extraction. |
| `enable_encoding_detection` | `bool` | `True` | Count escape sequences as hidden content. |
| `sensitivity` | `float` | `1.0` | Scales the informational `threat_score` on the result; it does not change the verdict. |
| `enable_heuristic_analysis`, `enable_sequential_analysis`, `enable_entropy_analysis` | `bool` | `True` | Accepted for compatibility; the structural heuristics they switched are gone. |

<Warning>
The screen is a first look, not a guarantee. Keep governance on for any
agent that can act: an injection that phrases itself in a way no pattern
knows still cannot make the agent do what the policy does not allow.
</Warning>

## Privacy boundaries

The runtime has a separate privacy policy for what is kept **about** a run. By
default it redacts email addresses, phone numbers, Social Security numbers and
valid payment card numbers from one place: the record — telemetry, and every
trajectory and export made from it. The run itself works with real data. The
model reads it, the conversation memory and the workspace keep it, and the
events streamed to `on_event` and the answer `run()` returns carry it: an agent
asked to find a user's email has to be able to give it.

```text
model input   memory   workspace   stream   answer   │   telemetry
    real       real       real      real     real    │   [REDACTED_EMAIL]
```

Turn a boundary on where it must hold no personal data, knowing what that
costs. `redact_stream` and `redact_public` change what the application
receives. `redact_memory` and `redact_workspace` change what the agent works
from: a later turn and a resumed run continue from that memory, and the files
are what it writes. The repository steward twice pushed a `pyproject.toml`
whose author email had become `[REDACTED_EMAIL]` — once through a redacted
workspace, once because a resumed run rebuilt its approved call from redacted
memory. `redact_model_io` keeps personal data from the model provider, and the
model then cannot use it.

Configure it through `agent_config["privacy_config"]`:

```python
agent_config = {
    "privacy_config": {
        "enabled": True,
        "redact_memory": False,
        "redact_workspace": False,
        "redact_telemetry": True,
        "redact_stream": False,
        "redact_public": False,
        "redact_model_io": False,
        "categories": ["email", "phone", "ssn", "credit_card"],
    }
}
```

Each boundary can be disabled deliberately for an integration that has its
own data controls. The effective privacy policy fingerprint is recorded in
telemetry metadata so traces show which policy produced them.
