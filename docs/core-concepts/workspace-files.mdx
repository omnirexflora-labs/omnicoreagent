# Workspace Files

Every agent has a workspace: a folder where it writes notes, plans and
finished work with file tools, and where you can put files for it to work on.
It is on local disk by default (`./workspace/files/`), or in S3 or R2 when
several machines need the same files.

## The agent writes a file

Workspace files are on by default; there is nothing to switch on.

```python
import asyncio
from pathlib import Path
from omnicoreagent import OmniCoreAgent

async def main():
    agent = OmniCoreAgent(
        name="planner",
        system_instruction="Keep notes and plans in workspace files. Answer in plain text.",
        model_config={"provider": "openai", "model": "gpt-5.4-mini"},
    )
    result = await agent.run(
        "Create notes/plan.md with a three-item checklist for launching a blog, "
        "then read it back and tell me the three items in one line."
    )
    print(result["response"])

    trajectory = await agent.get_trajectory(result["trace_id"])
    for step in trajectory["steps"]:
        for call in step["tool_calls"]:
            print("step", step["step"], "->", call["tool_name"], call["arguments"].get("path"), call["outcome"])

    print(Path("workspace/files/notes/plan.md").read_text())
    await agent.cleanup()

asyncio.run(main())
```

```text
Choose a blog niche and target audience; set up the blogging platform and domain; draft and publish the first three posts.
step 1 -> write_file notes/plan.md success
step 2 -> read_file notes/plan.md success
- [ ] Choose a blog niche and target audience
- [ ] Set up the blogging platform and domain
- [ ] Draft and publish the first three posts
```

The agent's `notes/plan.md` is `./workspace/files/notes/plan.md` on your disk.
What it writes will differ on your run; where it lands will not.

## Give the agent your files

To give the agent existing files — a project to review, data to analyze — put
them under the workspace's `files/` folder before the run. This example also
moves the workspace to `./review-ws`:

```python
import asyncio
from pathlib import Path
from omnicoreagent import OmniCoreAgent

# Seed the workspace with a file before the run.
seed = Path("review-ws/files/project/app.py")
seed.parent.mkdir(parents=True, exist_ok=True)
seed.write_text(
    "def average(numbers):\n"
    "    return sum(numbers) / len(numbers)\n"
)

async def main():
    agent = OmniCoreAgent(
        name="reviewer",
        system_instruction="You review code. Answer in plain text, in two sentences at most.",
        model_config={"provider": "openai", "model": "gpt-5.4-mini"},
        agent_config={"workspace_config": {"workspace_dir": "./review-ws"}},
    )
    result = await agent.run("Review project/app.py. What input breaks it?")
    print(result["response"])

    trajectory = await agent.get_trajectory(result["trace_id"])
    for step in trajectory["steps"]:
        for call in step["tool_calls"]:
            print("step", step["step"], "->", call["tool_name"], call["arguments"], call["outcome"])
    await agent.cleanup()

asyncio.run(main())
```

```text
`average([])` breaks it with a `ZeroDivisionError` because `len(numbers)` is 0.
step 1 -> ls {'path': '.'} success
step 2 -> read_file {'path': 'project/app.py'} success
```

`review-ws/files/project/app.py` on disk is `project/app.py` to the agent's
tools. When the agent runs commands in a [sandbox](/docs/core-concepts/execution),
its workspace files are copied in too.

## How it works

The workspace has three areas:

| Folder | Holds | Written by |
|---|---|---|
| `files/` | The agent's files, and the ones you seed | The agent's file tools, and you |
| `artifacts/` | Tool results too large for the model's context, saved for the agent to read back in parts ([context engineering](/docs/core-concepts/context-engineering)) | The runtime |
| `telemetry/` | The record of every run ([observability](/docs/how-to-guides/observability)) | The runtime |

The agent works in `files/` with these tools:

| Tool | Arguments | What it does |
|---|---|---|
| `ls` | `path` (optional) | List a folder |
| `read_file` | `path` | Read a file |
| `write_file` | `path`, `content`, `mode` | `create` (default; refuses to replace an existing file), `append`, or `overwrite` |
| `edit_file` | `path`, `old_str`, `new_str` | Replace every occurrence of a string |
| `insert_file` | `path`, `insert_line`, `insert_text` | Insert text at a line (1-based) |
| `delete_file` | `path` | Delete a file or folder |
| `move_file` | `old_path`, `new_path` | Rename or move |
| `clear_files` | — | Delete everything in `files/` |
| `glob` | `pattern`, `path` (optional) | Find files by pattern, such as `**/*.md` |
| `grep` | `pattern`, `path`, `include`, `case_sensitive`, `max_matches` | Search inside files; returns `path:line:content` |

These are workspace tools, not a shell: every path is relative to `files/`,
and a path that leads outside it is refused. They work the same on local disk,
S3 and R2. Their names are reserved while workspace files are on, so give your
own tools other names. Under governance each is a capability —
`workspace.files.read`, `.write`, `.delete`, `.move`, `.clear` — that a policy
can allow, ask about or deny ([security model](/docs/core-concepts/security-model)).

## Where the workspace lives

<Tabs>
  <Tab title="Local disk (default)">
    ```python
    agent_config = {"workspace_config": {"workspace_dir": "./workspace"}}
    ```

    One machine. Files survive restarts; other machines cannot see them.
  </Tab>
  <Tab title="S3">
    ```bash
    pip install "omnicoreagent[s3]"
    ```

    ```python
    agent_config = {
        "workspace_config": {
            "workspace_backend": "s3",
            "s3_bucket": "my-agent-workspace",
            "aws_region": "us-east-1",
            "prefix": "workspace",  # files go under workspace/files/ in the bucket
        }
    }
    ```

    Credentials: `aws_access_key_id` and `aws_secret_access_key`, or, when
    those are not given, boto3's usual chain (environment, profile, role).
    `aws_endpoint_url` points it at any S3-compatible store.
  </Tab>
  <Tab title="R2">
    ```bash
    pip install "omnicoreagent[s3]"
    ```

    ```python
    import os

    agent_config = {
        "workspace_config": {
            "workspace_backend": "r2",
            "r2_bucket_name": "my-agent-workspace",
            "r2_account_id": os.environ["R2_ACCOUNT_ID"],
            "r2_access_key_id": os.environ["R2_ACCESS_KEY_ID"],
            "r2_secret_access_key": os.environ["R2_SECRET_ACCESS_KEY"],
        }
    }
    ```

    All four R2 settings are required.
  </Tab>
</Tabs>

### Or from the environment

With no `workspace_config` at all, the workspace is read from environment
variables, so a deployment can choose it without code changes:

| Variable | Default | For |
|---|---|---|
| `OMNICOREAGENT_WORKSPACE_BACKEND` | `local` | `local`, `s3` or `r2` |
| `OMNICOREAGENT_WORKSPACE_DIR` | `./workspace` | local |
| `OMNICOREAGENT_WORKSPACE_PREFIX` | `workspace` | S3 and R2: the key prefix in the bucket |
| `AWS_S3_BUCKET`, `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_ENDPOINT_URL` | — | S3 |
| `R2_BUCKET_NAME`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` | — | R2 |

<Warning>
A `workspace_config` you pass replaces these variables entirely: none of them
is read, so `{"workspace_backend": "s3"}` alone fails for want of a bucket even
when `AWS_S3_BUCKET` is set. Pass everything the backend needs in the
dictionary, or pass no `workspace_config` and set it all in the environment.
(For S3, boto3 still finds credentials its own way when none are given.)
</Warning>

| | Local | S3 | R2 |
|---|---|---|---|
| Survives a restart | Yes | Yes | Yes |
| Needs cloud credentials | No | Yes | Yes |
| Shared by several machines | No | Yes | Yes |

## Options

| Setting (in `agent_config`) | Default | What it does |
|---|---|---|
| `enable_workspace_files` | `True` | Give the agent the file tools above. `False` removes them; the workspace still holds artifacts and telemetry |
| `workspace_config` | `None` (from the environment, else `./workspace`) | Where the workspace lives: `workspace_backend`, `workspace_dir`, `prefix`, and the S3 / R2 settings above |

Every setting is in the [agent settings reference](/docs/reference/agent-config).

## When things go wrong

<AccordionGroup>
  <Accordion title="ValueError: Tool name conflict: built-in workspace tools reserve these names">
    One of your tools has the name of a workspace tool. Raised by `run`:

    ```text
    ValueError: Tool name conflict: built-in workspace tools reserve these names when enable_workspace_files=True: read_file. Rename the app tool or disable workspace files for this agent.
    ```

    Rename your tool (`read_app_file`), or set `enable_workspace_files` to
    `False`.
  </Accordion>

  <Accordion title="ValueError: S3 workspace backend requires AWS_S3_BUCKET">
    Raised by `run` when the S3 or R2 settings are incomplete:

    ```text
    ValueError: S3 workspace backend requires AWS_S3_BUCKET
    ValueError: R2 workspace backend requires environment variables: R2_BUCKET_NAME, R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY
    ValueError: workspace_backend must be one of: local, s3, r2
    ```

    With a `workspace_config` dictionary, the settings must be in it
    (`s3_bucket`, `r2_bucket_name`, …): the environment is not read.
  </Accordion>

  <Accordion title="The agent cannot find the file I put there">
    Seeded files belong under `files/`: `./workspace/files/project/app.py`,
    not `./workspace/project/app.py`. And the workspace is relative to the
    working directory the agent runs in unless `workspace_dir` is absolute.
  </Accordion>

  <Accordion title="What the model sees when a file call fails">
    A failed file call is an answer to the model, not an exception; it usually
    corrects itself. It is recorded as the tool call's `error` (outcome
    `error` in the trajectory), with the same text. For example:

    ```text
    File not found: project/missing.py
    Invalid path '../../../etc/passwd' resolved outside workspace namespace.
    ```

    `write_file` in `create` mode on an existing file answers with a preview
    of it and `Use mode='append' or mode='overwrite'.`
  </Accordion>
</AccordionGroup>
